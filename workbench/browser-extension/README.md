# ERC Studio·飞书内嵌桥

Chrome / Edge Manifest V3 扩展。它只对 `*.feishu.cn` 的 `sub_frame` 响应移除阻止嵌入的响应头，并只允许 `studio.example.invalid` 作为顶层站点时使用飞书 Cookie。不读取、复制或上传 Cookie。

## 本地加载

1. Chrome 打开 `chrome://extensions`，Edge 打开 `edge://extensions`。
2. 开启「开发者模式」。
3. 选择「加载已解压的扩展程序」，选择本目录。
4. 重新打开 `https://studio.example.invalid/`。

扩展未安装时，工作室不尝试直接嵌入飞书，避免重现「已阻止此内容」。

## 0.2.0 蚁小二内嵌认证交接

新增 `www.yixiaoer.cn/web/*` 的MAIN-world子框架脚本；同时要求父页面referrer为工作室。本人已明确确认新增域名权限和重载。脚本只在蚁小二自身origin读取本人已有网页登录token，交给该页面原有auth处理器，由原服务核验本人和团队；不把token发送给工作室、服务器、日志、磁盘或CLI，不复制Cookie。没有本人会话时报告缺失，不伪造token、不自动登录。

原有飞书DNR规则不变。蚁小二本次没有修改响应头、后端接口或官方源码。精确父子source/origin校验、离页停止、供应商auth日志脱敏和发布人工确认保留。加载/auth-submitted不当成功，只有官方auth-ready及实际编辑器可见才通过。当前官方脚本的auth消息结构属于本次观察到的版本契约，供应商变更时需重新验收。

### Chromium存储分区

Edge第三方子框架的localStorage与独立打开官方页分开。内嵌会话缺失时在官方子页面显示“复用本人登录”按钮，调用 `document.requestStorageAccess({cookies:true,localStorage:true})` 后只通过返回handle读取该官方站点自己的token；官方服务仍执行登录校验。已有cookie访问许可/已授予访问时自动重新取得handle，不在父页面存放token。iframe仅新增 `allow-storage-access-by-user-activation`；未授权、被浏览器拒绝、官方会话失效分别保留本人处理，不修改浏览器全局隐私选项。

## 0.3.0 公众号与X渠道

仅新增 `mp.weixin.qq.com`、`x.com`；发布页顶部小栏目分别内嵌两站官方页面。`publisher-session.js`只在对应官方origin及工作室referrer的子页面运行，必要时提供浏览器原生Storage Access按钮；不读Cookie、localStorage、凭据或业务内容，不自动发文。DNR第3条仅对工作室发起的这两站sub_frame响应放开嵌入限制，所有独立官网页、其他域与脚本资源保持原响应头。扩展权限和响应头例外须本人明确确认后重载；已有飞书与蚁小二规则保留。

## 0.3.1 公众号扫码诊断

`wechat-diagnostics.js`仅在工作室内嵌的mp.weixin.qq.com运行，观察原页面已有XHR的startlogin结果及二维码图片失败事件，输出HTTP状态/数字ret，绝不输出Cookie、uuid、token、请求体或二维码。域名权限未增加；只用于取得根因证据，不代表二维码问题已修复。真人扫码、验证码与登录仍由本人完成。

## 0.4.0 公众号固定本机容器

工作室仅嵌入本扩展的publisher-host.html，容器收到来自工作室父窗的固定初始化消息后，只加载mp.weixin.qq.com。背景先确认当前扩展发起的公众号子框架头部规则已注册；失败不加载，不静默降级回旧扫码失败链路。只对工作室暴露HTML/JS/CSS，容器无Cookie API、存储读取、任意URL、网络代理或发布自动化。新增权限为固定资源可被工作室引用，官网域名权限未增加。网页CSP与已验证的本机扩展ID绑定；真实登录保持仍以本人当前后台界面为准。

### 0.4.1 并行更新兼容

总版本统一为0.4.1；保留已有DOM-ready启动兼容及蚁小二组件标识0.3.2。公众号容器权限、固定目标和不读取Cookie的边界保持不变；不得用旧组件版本号覆盖整个扩展版本。

## 0.3.2 朋友首次使用闭环

原0.3.1仅复用已存在的本机蚁小二token，未安装桥时发布页仍直接创建iframe，没有首次官方登录入口。0.3.2在工作室先检查本机桥能力及版本；缺失时不加载空转iframe，显示本机安装/更新步骤。桥标记等待documentElement出现再写入，避免document_start时空节点导致启动失败。

官方子页面提供“登录蚁小二”临时认证窗口和“已完成登录，恢复内嵌”。本人完成登录后，在官方origin通过Storage Access读取自己的会话；弹窗只发送带nonce的非凭据完成信号给原官方子页，核验source/origin/nonce，不向工作室传token。只有官方auth-ready才关闭本人这次打开的认证窗口；auth-failed重新显示身份/团队核验入口，不清旧存储或自动换账号。认证窗口外的编辑器仍完整内嵌，微信/X原有流程不变。

朋友需各自在桌面Chrome/Edge安装/更新0.3.2并本人登录蚁小二。飞书四人白名单不等于蚁小二团队成员资格；如看不到工作室账号，须由蚁小二管理员在原平台确认团队邀请/权限，不复制主账号登录或CLI Key。实际朋友设备的本人扫码、团队资格及重启保持独立验收。

当前发布包为0.4.1，包含公众号容器与上述蚁小二首次使用修复；0.3.2为蚁小二bootstrap能力标记，朋友应下载当前完整包并重载，不寻找旧版独立包。

更新时替换已有内嵌桥目录并在浏览器扩展页重载；不要同时启用两个版本。没有旧桥的朋友才加载新目录，权限仍由本人确认。

## 0.4.2 公众号编辑器留在内嵌页

微信官方子页面收到本机容器可信握手后，仅将用户激活的同站新窗口导航交给原frame；目标严格限HTTPS mp.weixin.qq.com，不接受用户名密码URL或任意域名。URL仅存在官方页与本机容器内存，不转发给工作室服务器，不解析Token、不读Cookie。认证/下载/跨站与显式组合键行为不接管；未打开本机容器的独立公众号页保持原样。没有真实业务写入测试，实际编辑/保存由本人验收。
