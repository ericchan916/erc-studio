## 当前结构

- workbench/src：原生 Electron/IPC、独立账户会话、任务/资料、内容、指标/活动投影。
- workbench/web：原工作台界面、本人对话、内容/制作、账号/数据、选题/活动与工作流 UI。
- workbench/backend：认证网关、持久对话/上下文、内容刷新、制作/发布执行及指标适配。
- workbench/shared/notification-center：原统一通知状态机与 CardKit 校验。
- contentbase：原 v0.3 兼容 CLI/HTTP、受审写计划、实际冻结素材、幂等和原任务核验。
- docs/modules + docs/workflows：12 个模块书与 22 条原工作流合同；后台服务不因存在文档就已安装。

## 必须保留

原工作台结构；原表业务权威；本人资源/明确 Profile/user；人审与准确版本；未知保留原 key/state/回执；成员归属；远端页无主窗口执行能力；真实上传/受理/终态/公开/登记分别验收。不要把查看模式当认证或业务 mock，不把两种队列的审批互认。

## 首次审查重点

1. 配置外置后的 Profile / URL / runtime root / 模型与 Skill 资源传递，是否仍有原机绑定或静默读取旧状态。
2. Native、网页适配与兼容 CLI 各入口权限/版本/幂等、未知核验一致性；两条发布路径互不自动重放。
3. 表/字段/记录准确绑定、完整分页、身份缓存与换身份隐藏；公式/结构复制不带旧人员/对象。
4. 原模块测试适用性、真实 UI 对照与缺资源状态；不能用旧测试总数替新代码验收。
5. 精确白名单、vendor 许可/摘要、构建包元数据、Git 跟踪/历史与最终远端字节。

写复现/根因/改动、确切命令/输入/退出码、失败/跳过、截图、未验证层和回滚；更新同模块书、机器索引、协议及调用方。使用本仓库 PR 模板。只提交相关源码，不加入私人配置/业务 MD/状态/日志/媒体；不把源码访问当真实写表或发布许可。
