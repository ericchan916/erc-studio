# 隐私与开源边界

## 公开的是通用实现，不是某个人的公司

本仓库从独立公开候选工程开始，仅包含通用代码、规则、虚构示例和自动测试；不附带原运行系统或原 Git 历史。首次启动必须由使用者绑定自己的资源，没有隐藏默认账号或业务对象。

## 必须排除

- 个人姓名、联系方式、账号、组织 / 群聊 / 表格 / 租户主键和实际机器目录。
- 原品牌 / 头像 / 三维资产、截图、授权二维码、浏览器会话和 Cookie。
- 密码、API Key、App Secret、OAuth Token、真实 CLI 配置和任何运行凭据。
- 原业务文档、私有提示词 / Skill、媒体、日志、数据库、缓存、执行回执和历史。
- 原系统服务名、部署目录、生产域名、LaunchAgent 及未公开依赖源码。

示例使用 `YOUR_` 类型槽或虚构数据；测试明确使用合成输入和替身 CLI，不包装成真实验收。

## 使用者数据在哪里

| 内容 | 保存位置 |
|---|---|
| 业务记录与内容阶段 | 使用者自己指定的飞书原表 |
| 账号 / CLI 凭据 | 供应商 CLI 自己的配置空间 |
| 绑定配置 | 使用者显式指定的私有配置路径 |
| 计划、原文快照、上传元数据、幂等、发布回执 | 源码外的私有技术 state |
| 公开代码 / 示例 / 文档 | 本 Git 仓库，不含前述真实内容 |

默认 state 是 `~/.local/state/content-company-base`，可通过 `CONTENTBASE_STATE_DIR` 指定其他源码外目录。state 可能包含你自己的稿件和作品信息，不因为它叫“技术队列”就可以公开。目录权限只是一层限制，不是恶意同用户进程隔离。

底座不要求在 dotenv 或配置 JSON 中填 Token / API Key，不把供应商授权搬进项目。Profile、Base token、table ID 虽不是登录密码，仍是实际绑定信息，应保持私有。

## 发布代码之前检查实际产物

1. 采用明确文件白名单发布；检查 Git 跟踪清单、真实配置误入、测试 / 日志 / 缓存 / 媒体 / 数据库和二进制。
2. 扫描个人标识、凭据格式、机器绝对路径、业务域名、原服务 / 租户 / 账号 ID；人工检查文档、提示词和资产的语义泄露。
3. 构建时也检查 wheel / 源码包的实际文件列表、归属与压缩头元数据。源码干净不代表分发包一定干净，`.gitignore` 也不会移除已跟踪文件。
4. 在干净目录运行；确认不读取旧项目、供应商凭据以外的历史环境或源码内 state，关闭网络的合成测试不会访问真实服务。
5. 记录已检查和未检查范围。扫描零命中是工具结果，不是“永久保证不存在任何个人信息”的证明。

供应商服务和平台的条款 / 费用 / 依赖许可仍需使用者核实；本仓库不附带私人授权或第三方私有源码。

## 反馈与备份

问题报告只分享脱敏错误类别、版本和复现步骤。不要上传完整 auth 输出、配置、技术 state、账号列表、原稿、媒体或网页访问 Token。备份私有 state 时按本人数据处理；回滚代码保留状态，不能凭“回滚”抹掉已经发生的外部投递或写表。

## sdist 的归属元数据

仅扫描源码内容不足以排除构建者信息：setuptools 的 sdist tar 默认可携带本机 UID/GID、uname/gname、PAX 时间和 gzip 文件名。公共构建后端将 tar 归属设为 0 / 空名称、mtime 0、文件 / 目录模式 0644 / 0755；gzip 不保存文件名、时间设为 0。重开校验每个成员的类型、路径、元数据与原字节 SHA，不接受符号链接、硬链接、遍历或重复路径。

旧的未通过这一门禁的 sdist 应作为私有诊断资料隔离，不继续分发；中性源码压缩包与 wheel 的检查分别记录。editable wheel 是私有安装产物，不作为公开发行物。
