# 完整验收边界

> v0.4 分层说明：本文件描述保留的兼容 CLI / 控制面。完整原工作台见 [模块地图](MODULE_MAP.md) 与 [原生接入](WORKBENCH_SETUP.md)；源码只读查看不等于业务已接通。
这张表对应项目目标，不以局部测试替代整个内容流程。每项必须有直接证据；合成数据、只读检查和真实副作用分开记录。

| 必须证明的要求 | 证据与当前边界 |
|---|---|
| 开源源码、测试、说明和发行包不携带开发者私人信息 | 精确白名单、全文与外置私人标识检查；干净副本构建 wheel / sdist；归档重开逐文件验算。源 Git 历史、运行数据、供应商配置与截图不进入发行物 |
| 新使用者能按说明启动 | 独立环境构建与安装、源码 / 安装后 CLI、占位配置明确拒绝真实接入；README、配置、Skill 与 HTTP 契约齐备。第三方设备和本人账号仍需真实验收 |
| 使用真实飞书生态 | 显式 Profile / user、指定 Base / 表、服务端身份、完整字段分页及原记录；本地计划只是技术状态。真实读取已验证，真实写入与同身份回读仍待本人批准 |
| 使用真实蚁小二生态 | installed yxer 的账号、schema、动态收据、上传、validate / dry-run、本人冻结预览确认及原任务查询。真实只读与静态准备已验证，上传和正式投递仍待本人授权 |
| Agent 无需更换自身引擎 | CLI 与 HTTP 共用 Service，文本 / 文件由外部 Agent 交付；独立客户端协议测试通过。没有内置模型，没有宣称任何聊天产品天然具备执行能力 |
| 编辑不基于列表预览或过期素材 | 完整原记录 API、来源摘要、两次计划门禁、原文对比与本人 rebase；保留本地稿。源变化或身份变化停止旧计划 |
| 审核只作用于当前精确版本 | 写计划 / 发布包摘要、真实操作者和目标绑定；过期、字段 / 正文 / 素材 / 通道 / provider 变动作废。正文完整保留、不截断 |
| 并发、重启与丢回执不重复业务执行 | 稳定请求 key、原媒体 ID、资源锁、进程代际和真实僵尸检查、未知只读核验、原始回执持久化；数据库和临时文件保护。没有远端原子 CAS，也不是恶意同 OS 用户进程隔离 |
| 单用户身份不自动共享供应商凭据 | 每个 state 固定最初核验的本人；换人需要独立 state / 配置和本人供应商授权。provider / operator 元数据只作指纹绑定，不冒充供应商当前用户或平台稳定 UID 已验证 |
| 发布受理与作品公开区分 | submitted / taskSetId 只表示受理，query 保留平台原生状态；本人打开作品后才另建已发布登记计划。平台公开可见仍待本人验收 |
| 内容复盘可追溯 | 平台、作品 ID、带时区观察时间、数值或明确缺失；事实 / 判断分开，人审后写回飞书。真实登记与复盘回读仍待业务验收 |
| 回滚不覆盖真实业务或用户数据 | 原源码备份、补丁与逐命令记录；在隔离副本执行回滚和恢复。代码回滚不撤销已投递作品或外部写入，不删除技术证据 |

## 尚需本人提供的验收输入

1. 明确允许写入的飞书测试 Base / table / 记录；原业务表保持不动。
2. 本人可公开的素材、准确蚁小二账号、类型和 cloud / local 通道。
3. 本人核对冻结预览并确认正式投递；完成后打开真实作品确认公开 URL。

在这些证据齐备前，项目属于实现与本地验证阶段，不宣布完整真实业务闭环已完成。已知限制和实际验证范围见 [当前状态](STATUS.md)。
