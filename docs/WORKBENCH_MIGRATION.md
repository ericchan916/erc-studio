# 原工作台迁移与验收矩阵

## 为什么重做这次交付

v0.3 是缩减内容闭环，不是原工作台的脱敏版。v0.4 将原工作台实现作为实际代码迁入；兼容 CLI 保留，入口和文档明确区分。个人信息剥离不等于删除模块或重新设计另一产品。

## 已迁移源码

- 原生 Electron 主进程/preload/账号隔离/任务和文件夹页面；不是把浏览器登录当 CLI 身份。
- 原主页、本人对话、内容/制作、账号/数据、活动、选题及工作流界面；私人形象资产不分发。
- 本人认证网关、持久对话与上下文、内容刷新、原任务发布、制作执行/私有工程、指标适配、共享通知中心。
- 精确模块书、分目录 AGENTS、机器索引、按模块读取器；旧 CLI / HTTP / 审核包代码继续保留。

## 有意排除

真实配置、人员名单、租户/账号/表/目录绑定、原业务 MD、原稿/媒体、GLB、授权、Cookie、数据库、二维码、私有日志/回执、已安装 App 和原 Git 历史。旧部署文件不能用于自动覆盖使用者已有 App/Bridge。第三方资源保留许可证，不冒充自有代码。

## 对照检查

导航和源文件的迁移与 UI 实屏分开记录；无默认真人账号或演示业务数据。只读模式不调用模型、CLI、上传或发布，不伪装身份。任务/内容/官方发布/资料库需要本人资源时显示未配置，不用假内容填满页面。

## 回滚

保留改动前 Git SHA、源码哈希、补丁及精确验证记录；用隔离副本演练恢复。源码回滚保留 state/凭据/历史/外部记录；GitHub 回滚应以新反向提交推进，不强推改历史。

## 原回归的迁移适用性

个人 GLB 与依赖私人已安装渲染包的历史用例保存到 tests/historical，不属于默认公开验证；对应源功能缺资源仍未就绪。原源码的 content-embed-state 用例在本次改动前即复现 7 项夹具接口漂移（缺浏览器 transport），本次在公开副本中修正夹具依赖。已选择 backend/profile/账号的测试显式构造私有槽和合成资源；不恢复原开发者默认服务地址。原项目未修改。

当前原网页发布使用官方蚁小二内嵌入口，旧自定义编辑器测试保存在 historical，明确不计默认通过数；现在的发布首用/内嵌/授权用例仍单独执行。

GitHub 内容检查识别到原 RUM 签名测试的腾讯云凭据形状示例（字面值以 EXAMPLE 结尾，非本人真实凭据）；改为明确 YOUR_ 合成槽，并仍由独立 HMAC 算法核验签名。新增 AKID 本地门禁，未关闭 GitHub 保护、未修改供应商程序或绕过校验。
