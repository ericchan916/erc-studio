# 架构：业务权威、控制面与执行适配器

> v0.4 分层说明：本文件描述保留的兼容 CLI / 控制面。完整原工作台见 [模块地图](MODULE_MAP.md) 与 [原生接入](WORKBENCH_SETUP.md)；源码只读查看不等于业务已接通。
## 为什么有这个底座

Agent 擅长生成内容，但聊天历史不适合作为公司业务账本，也不应绕过发布确认。底座把生成结果变成可审核、可执行、可追溯的计划；使用者的飞书保存业务事实，蚁小二执行跨平台发布。

```text
Agent / 本人
  │ CLI 或本机 HTTP
  ▼
Service（统一守护）
  ├─ 飞书适配器 ─ lark-cli / 显式 Profile / user ─ 指定 Base 表
  ├─ 发布适配器 ─ yxer / 指定账号与通道 ─ 平台
  └─ 私有技术 state ─ 输入摘要 / 身份绑定 / 幂等 / 执行回执
Web 工作台只调用同一 Service，不另造一套业务逻辑。
```

## 三类状态分开

| 对象 | 权威来源 | 本机用途 |
|---|---|---|
| 内容标题、正文、阶段、公开链接、指标、复盘 | 使用者的飞书表 | 限定读取快照与受审写计划 |
| 平台账号与发布结果 | 蚁小二 / 平台实际回执 | 本次账号快照、上传元数据、发布任务及核验结果 |
| 摘要、批准、幂等键、未知执行 | 本机技术 state | 防重复、约束执行、保留证据，不作为另一个公司账本 |

第一次启动不读取其他项目、机器历史、浏览器 Cookie 或共享业务目录。配置只绑定使用者显式选择的对象。

## 内容闭环

1. `sync` 读取飞书表；Agent 根据用户指定记录生成内容。
2. `draft` 读取字段 / 目标记录、核验身份、执行 CLI dry-run，冻结标题 / 正文及目标记录快照，生成飞书写计划；不会直接写表。
3. `approve` 本人审核摘要及完整预览；`apply` 核验身份、记录与字段摘要仍匹配冻结计划，执行并回读。草稿写为“待审核”，不冒充发布批准。
4. `publish-prepare` 取指定记录和账号，读 schema / 动态资源，上传素材，validate + dry-run，形成发布冻结预览。
5. 准备时复制并冻结实际媒体，manifest 绑定字节 / 顺序 / 角色；UI 认证取字节并核验 hash 后展示图 / 视频 / 独立封面，或导出完整私有审核包。本人完整观看并明确声明后，才以 media_review_digest 连同冻结摘要在 `publish-submit` 确认；这次确认才是当次稿件的发布批准。未过期 ready 可以跨 CLI 进程：提交重新查询原动态对象与 schema / 账号，重做 validate / dry-run，但不上传、不修改冻结包；然后只投递同一 payload 与通道。
6. `publish-verify` 查询原任务，不重发。取得平台回执后，本人打开作品确认公开 URL。
7. `published` 生成公开作品登记写计划；本人批准并 `apply` 才改飞书。
8. `review` 使用明确提供的指标与复盘结论生成新写计划，经审核 / 回读进入下一轮。

## 一致性与恢复

- 一个 state 首次核验固定本人；换人必须独立配置 / state 和本人供应商授权，不借用旧绑定或清旧数据库。
- GUI 编辑另取完整原记录，提交 expected_source；来源变化保留稿件，由本人核对最新原文后 rebase，不静默换摘要。
- 计划绑定生成时的 user 身份、目标记录快照和冻结输入摘要；提交前再次核验。旧批准不覆盖变更后的记录或素材。
- 同一业务请求保持同一 `--key`。如果同键输入不同，应处理冲突，不使用新键绕过。
- 外部写命令超时、进程中断或缺少可靠回执时标记未知；先按原记录 / 原任务核验，不能直接判断“未执行”。非发布 unknown 可用 `verify-write` 只读比对当前目标字段，匹配后仅在本地标 applied，不证明原请求回执或执行者。
- 正式发布重启不自动重放。已保存的私有 receipt.json 可以恢复任务 ID 供只读查询，不再次投递。受理、平台结果、公开可见、飞书登记是独立层级。
- 同一 state 内使用按远端 Base / table / record 的跨进程资源锁；恢复不会把仍存活进程的操作标未知。已提交同源或未知执行不能通过换 key / 修改无关配置绕过；这仍不是飞书远端事务。
- inspect / API operations 按当次本人身份和当前配置在服务端过滤，避免跨配置展示私有材料。
- 飞书 CLI 没有远端原子 compare-and-swap；这里是本地快照的乐观门禁。读检查与实际写入之间仍有竞态窗口，首版应由单用户串行操作，不宣称多写入者事务隔离。
- 恢复程序和回滚保留技术 state；代码回滚不撤销外部业务动作，也不抹掉本次证据。

## 运行与信任边界

Python 3.11+ 标准库；供应商 CLI 由使用者安装和授权。运行器以参数数组调用 CLI，不执行拼接 Shell。项目不读取 / 复制供应商凭据；CLI 在本人用户环境使用其原配置。

Web 只监听 `127.0.0.1`，需本机生成的访问 Token，配置与技术 state 位于源码外。这是单用户本机控制面：TTY 输入或浏览器按钮不构成恶意同用户进程隔离，访问 Token 也不构成多用户 RBAC。不要将服务通过公网、反向代理或共享主机直接开放给他人。

没有内置模型或某一家 Agent 会话依赖。支持执行 CLI / HTTP 的 Agent 可以生成草稿并调用底座；人审动作仍由本人完成。MCP、平台插件、多人模式不属于首版交付承诺。

绑定已有准确 table ID 时直接使用 lark-cli +table-get；随后完整分页读取该目标的字段。不会把 +table-list 默认前 50 张当作全部表，也不因目标在后页误报缺失。
